# EFM3 Electricity Forecast Lab

**状态：active**  
**初始化日期：2026-09-21**  
**定位：成熟电力预测主项目的隔离研究实验室**

## 1. 为什么建立实验室

主项目 electricity_forecast_model2.5 已经形成稳定的 24 点/96 点生产链路、数据契约、ledger 状态和部署流程。新需求如果直接改动主项目，容易扩大影响面、破坏可复现性或污染正式产物。

本实验室提供一个安全隔离区：

- 每个一级子目录代表一个新功能或独立实验；
- 先在实验室中完成设计、实现、测试、泄漏审计和结果复盘；
- 研究成熟后，再由用户明确批准是否制定主项目接入补丁；
- 实验室结果不等于生产结果，不改变主项目当前行为。

以后新增功能时，直接在实验室根目录建立新的一级子目录，并让该功能尽量自包含。不要让功能依赖主项目的绝对路径、临时 outputs 或未记录的本机状态。

## 3. 工作流程

1. 在功能目录中先写目标、输入/输出、时间边界、验收指标和失败条件。
2. 只复制该功能所需的数据和代码，记录来源路径、版本和哈希。
3. 先做泄漏审计和最小 smoke，再做完整实验。
4. 结果报告必须带状态标签、基线、跨时间窗口表现和运行环境。
5. 通过研究验收后，单独评估主项目影响面；未经明确批准，不修改主项目。

## 4. 首个功能：spread24_senior_review

这是从主项目 deliverables/spread24_senior_review 复制出的独立 24 点价差预测研究包，研究目标是预测 D 日 24 小时 Spread = DA - RT。

严格业务边界：

- forecast origin：D-1 14:00；
- D-1 仅使用 origin 前已发生的信息；
- 完整监督标签最晚到 D-2；
- 禁止使用 D-1 14:00 后实际值、目标日实际值或完整 D-1 标签；
- 不接入主项目正式 24 点/96 点生产链路。

功能目录内的 README、docs/、tests/ 和 outputs/ 是该实验的自包含资料。复制时排除了 .pytest_cache、__pycache__ 和 .pyc 等瞬态缓存；主项目原目录保留不变。

进入该功能目录后，可按其 README 执行：

    python -m pip install -r requirements.txt
    python run.py
    python -m pytest

完整运行前仍应先核对数据快照、依赖和配置；不要把实验结果直接写入主项目的 outputs/。

## 5. 与主项目的关系

- 主项目：生产事实源、正式入口和正式文档。
- 实验室：隔离研究区、候选功能和实验记录。
- 接入方式：实验完成后提交独立设计/补丁，由用户审核后再进入主项目。
- 当前初始化采用“复制而非移动”：保留主项目原始交付包，避免搬运动作破坏生产仓库。
