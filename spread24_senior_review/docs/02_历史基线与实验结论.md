## 2. 月度主要现象

当前独立结果大致：

```text
Jan Raw 54.70 / Bal 49.92 / signed MAE 106.84
Feb 52.83 / 50.67 / 79.62
Mar 51.61 / 51.48 / 91.03
Apr 52.22 / 50.98 / 77.56
May 62.63 / 57.13 / 72.18
Jun 53.75 / 51.91 / 92.66
Jul 60.75 / +Recall84.26 / -Recall20.44 / Bal52.35 / 84.70
Aug1-14 52.68 / 48.11 / 50.06
```

结论：

- Raw 有明显月份依赖；
- July 是典型类别偏置：Raw 不低但负类 recall 塌缩；
- 只看 Raw 会误判；
- 9-16 时段长期较难；
- 跨月稳定性比单月峰值更重要。

## 6. 从 V1.3 / V2.0 到 V2.1

V1.3 的 signed fusion：

~~~text
final y =
p*m_pos - (1-p)*m_nonpos
~~~

首先带来两个结构问题：

1. final sign 不由 Direction Head 单独决定；
2. p≈0.5 时 signed expectation 可接近0，即使真实 magnitude 很大。

V2.0 曾通过独立 KPI readout 修正最终输出：

~~~text
direction_hat = p >= 0.5
magnitude = p*m_pos + (1-p)*m_nonpos
signed_kpi = sign(direction_hat) * magnitude
~~~

并把硬隔离：

~~~text
Direction <- temporal only
Magnitude <- tabular only
~~~

改成：

~~~text
Direction = temporal primary + tabular auxiliary
Magnitude = tabular primary + temporal auxiliary
~~~

但正式训练前进一步审查发现，V2.0 仍存在目标错配：

- weighted BCE + tau=0.5 不严格对应 Raw Direction；
- p*m_pos+(1-p)*m_nonpos 不直接对应 |Y| MAE；
- signed L_point 会重新耦合两个正式 KPI；
- Direction 在 head 前 mean_k，未完整利用 TabM member-wise ensemble；
- selector 使用 MAG-POS/MAG-NONPOS，而正式 KPI 是 overall Magnitude MAE。

因此当前 canonical 已升级为 V2.1：

~~~text
Direction:
member-wise unweighted BCE
member-wise logits/probabilities
p_hat = mean_k(p_i)

Magnitude:
direct |Y| head
member-wise L1
magnitude_hat = mean_k(a_i)

Loss:
L_total = L_dir + L_mag

Selector:
DIR + MAG-ALL
~~~

V2.0 只保留为 target-alignment 对照，不再是正式主路径。

## 7. 当前研究问题

真正要验证：

1. tabular cross-feature state 是否为 Direction 提供增量；
2. temporal regime 是否为 Magnitude 提供增量；
3. A2 learnable cross-injection 是否优于 A0/A1；
4. official TabM ensemble 是否优于更简单 state encoder；
5. Stage B 是否真的优于 Stage-A-only / Full Retrain；
6. PLE、FFT、k、shadow policy 等工程机制是否有独立增益；
7. 严格边界下 direct Direction benchmark 能达到什么水平；
8. 24h sign transition 是否存在稳定、可利用的统计结构。

最终目标仍是：

~~~text
Raw Direction 跨月稳定向 70% 推进
同时 Magnitude MAE 不恶化
~~~

不能用单月、泄漏、类别 collapse 或 lockbox 调参换取“70%”。

## 8. 2026-09-26 E2-C3 Strong-role routing 筛查

**范围与状态：** E2-C3 是 `dir_only` 的研究筛查，不改变冻结 selector、正式特征、V2.1 canonical 或生产链路。R0 复用 F80/G0 锚点，R1/R2 各完成 28 个冻结 DEV 日的 CUDA+AMP formal runs（均 28/28 PASS）。预测起点和标签可见性按 `01_业务数据与防泄漏合同.md` 执行。没有扩大 DEV、调 threshold/calibration 或触碰 lockbox。

冻结分组为 Strong-BOTH 147、Strong-DIR 32、Strong-MAG 22、Forced-Core 10、Weak 11。R1 排除 Strong-MAG（Strong/Core 输入 189）；R2 排除 Strong-DIR（输入 179）；两者均保留 Weak 11。这里仅研究 Direction 路径，不对 Magnitude 能力作结论。

以 R0 为锚点，R1 的 Raw 差为 -1.34pp，Balanced/正类召回相关安全条件未通过；R2 的 Raw 点估计仅 +0.30pp。10,000 次按日聚类 bootstrap 中，R1-R0 的 Raw 95% CI 为 [-4.17pp, +1.49pp]，R2-R0 为 [-4.17pp, +4.61pp]，均跨零；窗口表现也未形成预注册的稳定优势证据。因此 Gate 为 **`NO_CLEAR_ROLE_EFFECT`**，不是角色筛选有效的证据，也不是对两种角色等效的证明。
